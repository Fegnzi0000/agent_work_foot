## 3. 本次产品与账号规则

| 原来 | 现在 |
|---|---|
| C 端邮箱注册、邮箱登录、微信登录、邮箱账号绑定微信并存 | C 端仅保留微信登录；公开邮箱相关接口返回 410 |
| 点击微信登录立即建立账号 | 先选择年龄段、主动同意当前协议，再获取微信 code；首次登录自动注册 |
| 简短隐私弹窗 | 独立完整用户协议、隐私政策和医疗过敏处理说明，可在登录前和设置中阅读 |
| 医疗过敏直接填写 | 成年人单独同意后可选填写，拒绝不影响基础功能；可撤回并清空在线数据 |
| 无未成年人分支 | 不满十四周岁暂不开放登录；十四至十七周岁可用基础功能，暂不开放医疗过敏录入 |
| 微信用户仍出现改密码/密码注销 | C 端移除密码操作，注销重新验证同一个微信身份 |
| 管理员列表要求邮箱必填 | 邮箱允许 null，仍校验非空邮箱格式，使用用户 ID 进行操作 |
| 管理员可给 C 端发临时密码 | 移除该操作，接口返回 410；管理员本人仍可改密码 |

“绑定微信并登录”的旧逻辑是：校验已有邮箱账号密码，再把当前微信关联到该邮箱账号。不是给微信新账号添加邮箱；先微信登录建号后再绑定旧邮箱会冲突。本次不再保留这个公开入口，不做自动账号合并。既有邮箱用户均为测试账号，保留数据但无法再通过邮箱登录。

年龄段是用户声明，不是实名认证。已声明十四至十七周岁的账号不能通过重新登录自行改成成年人；年龄更正需联系开发者核验。未成年人实际核验和保护仍是上线审查事项。

## 5. 接口变化（前后端必须配套）

所有路径以下以 `/api/v1` 为前缀，成功与错误外层响应结构保持不变。

| 接口 | 变化 |
|---|---|
| POST /auth/register | 关闭；格式合法的旧请求返回 410 EMAIL_AUTH_REMOVED |
| POST /auth/login | 关闭；返回 410 EMAIL_AUTH_REMOVED |
| POST /auth/wechat/mini-program/bind | 关闭；返回 410 EMAIL_AUTH_REMOVED |
| POST /auth/wechat/mini-program/login | 必须提交 code、accepted=true、termsVersion、privacyVersion、ageBand |
| GET /users/me/consent | 返回 current、ageBand、medicalAllowed |
| PUT /users/me/consent/medical | 请求 accepted；同意时 version 必须匹配，拒绝/撤回不要求新版本 |
| POST /users/me/cancel-wechat | 新增：code、confirmation="CANCEL"；校验微信归属后注销 |
| POST /users/me/cancel | 旧密码注销关闭 |
| POST /users/me/change-password | 仅管理员可用 |
| POST /admin/users/{id}/temporary-password | 关闭，返回 410 |

微信登录示例（code 必须来自客户端新调用，不能复用）：

```json
{"code":"fresh-wechat-code","accepted":true,"termsVersion":"2026-09-06.1","privacyVersion":"2026-09-06.1","ageBand":"ADULT"}
```

允许的年龄段为 `ADULT`、`AGE_14_17`，不接受 `UNDER_14`。协议过期或缺失的旧会话不能访问业务，也不能通过刷新绕过。前端遇到失效会话重新进入同意和微信登录流程。服务端同意记录是审计依据，不是对“真人确实阅读”的技术证明。

微信平台隐私授权与应用内协议是两层：按平台 `getPrivacySetting` 状态调用隐私授权，拒绝或失败不继续；不能强迫每次出现微信原生弹窗，也没有获取手机号/头像的假授权流程。

## 6. 数据库、注销与维护

新增 `V4__consumer_consent.sql`，不修改 V1-V3：

- `user_consents` 保存当前条款版本、声明年龄段、医疗同意状态和时间。
- `consent_events` 保存同意/撤回事件，不保存过敏正文。
- 普通用户安全版本递增，旧刷新令牌撤销，清除遗留普通用户强制改密状态；管理员不受影响。
- 历史过敏数据不推定已有同意，在未授权时不向应用返回；重新授权前保持受限，人工清理另行操作。撤回时删除在线过敏条目；不会因为第一次升级登录擅自删除历史业务数据。

注销会校验新的微信 code 是否对应当前账号，不允许换绑或自动注册；撤销全部会话并撤回医疗同意。仍采用软注销，微信绑定保留，因此不能直接再次登录或注册。

新增本机维护工具 `本地环境/manage-local-accounts.ps1`：

```powershell
# 创建管理员：交互输入账号与密码，不在命令行携带密码；重复运行不重置已有密码
powershell -ExecutionPolicy Bypass -File .\本地环境\manage-local-accounts.ps1 -Operation create-admin

# 先查看指定账号关联数据数量；替换为实际内部 UUID
powershell -ExecutionPolicy Bypass -File .\本地环境\manage-local-accounts.ps1 -Operation preview -UserId '<UUID>'

# 仅在核验归属、备份并审查预览后使用；要求再次键入精确确认文字
powershell -ExecutionPolicy Bypass -File .\本地环境\manage-local-accounts.ps1 -Operation purge -UserId '<UUID>'
```

清理工具只允许已注销的普通用户，拒绝活动账号及管理员。事务内处理微信绑定、会话、偏好、预算、食物、标签、记录、抽取记录、同意记录和审计关联，避免只删 users 留下残留。清理后微信可注册新账号，不恢复原数据。维护工具只在本机显式启用，启动在 loopback 随机端口，无公开提权/删除接口。它不是自动核验用户身份的系统；操作者须先核验请求。

软注销并非个人信息删除义务的替代品。公开上线前须落实分类保存期限、注销后清理、备份轮换和删除重放，不能只保留一个人工工具而无限期不处理数据。
